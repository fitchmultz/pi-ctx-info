## QX-001: node:test registration safe-calls allowance

- **ID and title:** QX-001 — aliased node:test registration calls are known-safe registrations, not floating promises.
- **Rule, option, or threshold; installed tool versions:** `typescript/no-floating-promises` `allowForKnownSafeCalls`; oxlint 1.94.0 with tsrs 7.1.0-beta.tsrs2.
- **Scope:** calls to `nodeTest`, `nodeIt`, and `nodeDescribe` — the only registration forms this repository uses — bound to the `node:test` package declaration origin. Every other option stays at its strict default (`ignoreVoid: false`, `checkThenables: true`, empty `allowForKnownSafePromises`).
- **Directive selectors/inventory and optional duplication bounds:** config-level allowance; no source directives. The machine-readable form is [`QX-001` in exceptions.json](exceptions.json).
- **Diagnostic and required contract:** without the allowance, every unawaited test registration in `breakdown.test.ts`, `snapshot.test.ts`, and `overlay.test.ts` fails `no-floating-promises`.
- **Actual compliant alternative and demonstrated quality cost:** awaiting registrations, async suites, or `Promise.all` collections change module evaluation and hook timing under node:test's registration model (standard §6.4), for all tests, with no behavioral gain.
- **Chosen adjustment and why its scope is appropriate:** `allowForKnownSafeCalls` matching **aliased** local names (`nodeTest`, `nodeIt`, `nodeDescribe`). Bare `test`/`it`/`describe` and context subtests such as `t.test()` stay flagged: name-matching that permits the context-subtest control is too broad (standard §6.4).
- **Structural comparison or unsafe-type evidence:** not applicable (no assertion involved).
- **Verification commands, relevant tests, and results:** requalified 2026-11-18 under `oxlint 1.94.0` + `tsrs 7.1.0-beta.tsrs2` + `@types/node 24.19.0` via `./node_modules/.bin/oxlint --deny-warnings <probe.test.ts>`: aliased `nodeTest`/`nodeIt`/`nodeDescribe` registrations exited 0; bare `test`/`it`/`describe`, `t.test()` context subtest, local `async function nodeIt`, imported `nodeTest` from a local helper, and an unawaited in-body promise each exited 1 with `typescript(no-floating-promises)`. `npm run check:policy` validates the `QX-001` baseline config and `npm test` runs the test suite.
- **Retained protection, lost detection, and established assumptions:** all other floating-promise detection is retained. Known detection limit (standard §6.4): declaration matching does not establish runtime calling context, so an imported registration invoked inside a running test would create a subtest while still matching this allowance. This repository's tests invoke subtests only through `t.*` context methods, which the allowance does not match.
- **Review and revisit trigger:** a node:test or oxlint upgrade that changes registration semantics or allowance matching, or any new registration form in the tests.

## QX-002: test-harness /ctx handler assertion

- **ID and title:** QX-002 — the shared test harness asserts the registered `/ctx` handler against the narrowed context double once, at the package boundary.
- **Rule, option, or threshold; installed tool versions:** `typescript/no-unsafe-type-assertion`; oxlint 1.94.0 with tsrs 7.1.0-beta.tsrs2.
- **Scope:** exactly one site, `ctxHandler` in `test-harness.ts`; the directive is tagged `QX-002` and cross-checked against [`QX-002` in exceptions.json](exceptions.json) by `check:policy` (unknown, stale, or extra directives fail).
- **Directive selectors/inventory and optional duplication bounds:** `ctxHandler: command.handler as (args: string, ctx: CtxCommandContext) => Promise<void>`; duplication bound: one.
- **Diagnostic and required contract:** the assertion narrows the handler registered against Pi's full `ExtensionCommandContext` to the `CtxCommandContext` contract the overlay consumes.
- **Actual compliant alternative and demonstrated quality cost:** building a full `ExtensionCommandContext` double (dozens of unrelated members) or widening the overlay's contract to all of Pi's context. The double deliberately implements only the members the overlay consumes; any member the overlay uses beyond them is missing on the double and fails closed at runtime. The single assertion encodes that boundary instead of duplicating Pi's entire context surface in tests.
- **Chosen adjustment and why its scope is appropriate:** one operation-bound directive at the package seam — not a file-wide or test-wide disable.
- **Structural comparison or unsafe-type evidence:** `CtxCommandContext` is a structural subset (narrowed `Pick`-based view) of the handler's declared context parameter, so the assertion is a pure narrowing at a boundary the runtime double enforces.
- **Verification commands, relevant tests, and results:** requalified 2026-11-18 under `oxlint 1.94.0` + `tsrs 7.1.0-beta.tsrs2`: removing the directive on a root copy of `test-harness.ts` triggers `error typescript(no-unsafe-type-assertion)` at line 90 (exit 1); keeping the directive passes `./node_modules/.bin/oxlint --deny-warnings .` with `reportUnusedDisableDirectives: "error"` (exit 0). `npm run check:policy` (manifest cross-check) and `npm run check:compat` pass; `npm test` runs the handler through the double across the test suite.
- **Retained protection, lost detection, and established assumptions:** every other type assertion in the repository must be a justified narrowing or guard-based; `reportUnusedDisableDirectives: error` keeps the directive honest. Assumption: the overlay consumes only `CtxCommandContext` members — extended by design when the overlay starts reading more context.
- **Review and revisit trigger:** the overlay consuming a new context member (extend the double and contract together), or Pi changing the command-context contract.

## QX-003: prerelease tsrs type-aware lint backend in place of stable oxlint-tsgolint

- **ID and title:** QX-003 — adopt prerelease `tsrs@7.1.0-beta.tsrs2` as the type-aware lint backend instead of stable `oxlint-tsgolint`.
- **Rule, option, or threshold; installed tool versions:** Standard §5.1 ("latest stable published releases of Oxlint, `oxlint-tsgolint`, Oxfmt"); `oxlint 1.94.0` (2026-11-16T12:26Z), `tsrs 7.1.0-beta.tsrs2` (2026-11-16T11:59Z), `oxfmt 0.79.0` (2026-11-16T12:27Z).
- **Scope:** `package.json` / `package-lock.json` `devDependencies` and type-aware lint execution (`oxlint` auto-discovers `node_modules/.bin/tsrs-lint`).
- **Directive selectors/inventory and optional duplication bounds:** none; backend package substitution only (not a source directive or config relaxation).
- **Diagnostic and required contract:** Standard §5.1 asks for stable published releases, whereas `tsrs` publishes prereleases only (`dist-tags.latest` is `0.25.0-ts7.1.0-beta`; `7.1.0-beta.tsrs2` is an untagged newer prerelease; stable `oxlint-tsgolint 7.0.2007` remains available).
- **Actual compliant alternative and demonstrated quality cost:** keeping stable `oxlint-tsgolint@7.0.2007` avoids a prerelease tool pin. In a matched A/B benchmark on `mitchs-m5-mbp` (Darwin arm64, `oxlint 1.94.0` running `oxlint --deny-warnings .`, median of 3 warm runs each via `OXLINT_TSGOLINT_PATH`), `oxlint-tsgolint@7.0.2007` took `0.13s` wall time and `267.5 MiB` maximum RSS vs `0.10s` wall time and `156.0 MiB` maximum RSS with `tsrs@7.1.0-beta.tsrs2` (`1.30x` slower, `1.71x` / `111.5 MiB` higher peak RSS; both exited `0`). Adopting `tsrs` also aligns this repository with the maintainer's shared Pi extension lint toolchain (`1.7x`–`3.4x` lower peak RSS across the 13-repo fleet).
- **Chosen adjustment and why its scope is appropriate:** owner-approved substitution of `tsrs@7.1.0-beta.tsrs2`; `oxlint 1.94.0` discovers `tsrs-lint` natively and fails loudly (`Failed to find type-aware linter executable`) if missing. All Appendix A type-aware rules and `tsc` compiler checks stay unchanged.
- **Structural comparison or unsafe-type evidence:** not applicable. A matched 7-diagnostic parity probe across `typescript(no-floating-promises)`, `typescript(no-misused-promises)`, `typescript(no-unsafe-assignment)`, `typescript(no-unsafe-return)`, `typescript(no-unsafe-member-access)`, `typescript(no-unsafe-type-assertion)`, and `typescript(prefer-promise-reject-errors)` reported identical diagnostics and line locations under both `oxlint-tsgolint@7.0.2007` and `tsrs@7.1.0-beta.tsrs2` (exit `1`), alongside the missing-binary fail-closed probe (`exit 1`).
- **Verification commands, relevant tests, and results:** `npm run check:compat` (lockfile, policy, format, lint, tsc, tests) passed on 2026-11-18 under `oxlint 1.94.0` + `tsrs 7.1.0-beta.tsrs2` + `oxfmt 0.79.0`, alongside the QX-001, QX-002, and 7-rule parity probes above.
- **Retained protection, lost detection, and established assumptions:** all type-aware lint rules, origin matching, and compiler checks stay enabled; diagnostic parity across the exercised type-aware rules is directly verified by the parity and QX-001/QX-002 probes above.
- **Review and revisit trigger:** first stable `tsrs` release, any `oxlint` upgrade changing backend discovery, or any type-aware diagnostic parity discrepancy.
